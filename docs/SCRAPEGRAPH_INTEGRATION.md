# ScrapeGraphAI evaluation

Open-source ScrapeGraphAI 2.3.1 was installed in isolated `.venv-scrapegraph`. SmartScraperGraph ran on **local HTML snapshots or fragments** from reviewed source pages, using local Ollama and telemetry disabled. It did not perform a live supplier fetch. No managed API or paid service was used.

The earlier Makhzan snapshot test with the 1.5B model returned seven rows despite a prompt for two current offers, including two stale offers and two truncated current titles. A constrained offer-section run yielded zero accepted rows. In the new direct-supplier test, a 474-character Makers product fragment containing the real H1, price and stock nodes was used. The 1.5B model returned the correct price, currency and listed availability, but truncated the title to `HC-05 Bluetooth Module` and missed `3.3V`. A 3B run with a targeted prompt once returned a complete four-field object, while later repeats returned `NA` or no validated fields. This is an unstable small sample, not an extraction accuracy benchmark.

The adapter now handles nested JSON or Python-literal dictionary output without executing code. It requires the full exact H1 for the name and checks price, currency and availability against scoped visible nodes. A partial name is rejected. The production run uses deterministic extraction, so no ScrapeGraphAI output is promoted into procurement evidence. Source: https://github.com/ScrapeGraphAI/Scrapegraph-ai.
